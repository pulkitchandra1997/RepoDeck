# Open Source Strategy

## Recommended License

Use MIT or Apache-2.0.

Recommendation: Apache-2.0 if patent protection matters, MIT if maximum simplicity matters.

## Repository Structure

Use a monorepo:

```text
repodeck/
  apps/desktop/
  crates/
  docs/
  .github/
  examples/
```

## Contributor Experience

The project should make contribution paths obvious:

- Good first issues.
- Architecture docs.
- Local setup guide.
- Test guide.
- UI contribution guide.
- Rust contribution guide.
- Design contribution guide.

## Governance

Start lightweight:

- Maintainer-owned roadmap.
- Public issue triage.
- Pull request templates.
- Code of conduct.
- Security policy.

Add formal governance only when contributors and maintainers grow.

## Community Positioning

RepoDeck should be positioned as:

- Local-first.
- Agent-aware.
- Git-host neutral.
- Open-source.
- Privacy-respecting.
- Useful without cloud.

## Contribution Areas

- Git adapters.
- Scanner performance.
- UI components.
- Agent config detectors.
- Package manager distribution.
- Documentation.
- Accessibility testing.
- Platform-specific installation improvements.
