# Preview Notes Authoring

Release bodies are generated by `scripts/generate-release-notes.cjs`; this guide
is not a static release body. No version record is added by the preview tooling PR.

For a future preview, include `docs/releases/versions/X.Y.Z-preview.N.json` in
the version-bump PR, replacing X, Y, Z and N with numbers. N starts at 1 and has
no leading zero. The file must match every application manifest and the tag.

Example schema (illustrative only, not approval to release this version):

```json
{
  "version": "0.2.0-preview.1",
  "channel": "unsigned-preview",
  "features": ["Describe a feature available in this version."],
  "fixes": ["Describe a fix since the preceding preview."],
  "limitations": ["Record native installer checks still pending for this version."]
}
```

Each section requires 1-20 plain-text entries of at most 500 characters. Use
"No feature changes in this preview." or "No fixes in this preview." where
appropriate. Do not omit known limitations. Only the five shown fields are
accepted. The file is limited to 32 KiB. Entries use ASCII prose with ordinary
punctuation; HTML, Markdown links/formatting, newlines and invisible controls
are rejected. Download links and verification details come from validated data,
not author-supplied URLs or arbitrary Git history.

The generated body starts with three installer links: Windows x64, macOS Apple
Silicon and macOS Intel. Unsigned/not-notarized status, OS restrictions, no
automatic updates, features, fixes and limitations remain visible. Exact source,
per-installer SHA-256 values, manifest links and verification caveats are in a
collapsible details section. Review the generated draft before publication;
links resolve for readers only after the draft is published.

The generator accepts the download-artifact directory structure, with one
`release-TARGET` directory per target, and writes a new output file exclusively:

```sh
node scripts/generate-release-notes.cjs release-assets release-notes.md
```

This command is intended for the tag workflow. It requires the exact checked-out
tag, GitHub source environment, read-authorized `GH_TOKEN`, `gh`, Cargo and
`origin/main`. It rechecks merged source and absence of any existing release;
it is not an offline Markdown formatter. Tests exercise generation with local
synthetic installers and do not execute or install them.
